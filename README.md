# hn-cpp26-trivial-loop-boundary-lab

Audit for **HN 49746406 — “C++26: Trivial infinite loops are no longer undefined behaviour”**

Tests the reviewer claim:

> “C++26 fixes infinite loops: endless loops are now defined, empty ones must yield, and the rule is portable to embedded/freestanding builds.”

**Verdict: the claim overgeneralises a narrow P2809R3 exception.** Only a syntactically *trivially empty* loop whose controlling expression is a *constant expression evaluating to `true`* (including implicit `true` for `for(;;)`) qualifies. An otherwise useless statement in the body, a non-constant condition, or a merely runtime-endless loop is not covered. A qualifying loop's body is replaced with `std::this_thread::yield()` on **hosted**; on **freestanding** the replacement is **implementation-defined**. Compiler support does not prove identical portable behaviour.

## Boundary under test

| Claim fragment | What P2809R3 actually establishes |
|---|---|
| **trivial infinite loop** | Trivially empty iteration statement + controlling expression is constant expression → `true` |
| **arbitrary nonterminating loop** | Runtime endlessness alone is not the P2809 definition |
| **busy wait** | Pre-P2809 UB allowed “assume terminates” optimisation; P2809 hosted replacement is `yield`, not a busy spin |
| **hosted replacement** | Body replaced with `std::this_thread::yield()` |
| **freestanding replacement** | Whether replacement occurs is implementation-defined |
| **compiler support** | Vendor claims are implementation-support evidence, not normative standard status |

Rule: **trivial infinite loop ≠ arbitrary nonterminating loop ≠ busy wait ≠ hosted replacement ≠ freestanding replacement ≠ compiler support.**

## What the primary sources actually say (verified 2026-09-19)

- **WG21 P2809R3 — “Trivial infinite loops are not Undefined Behavior”** (`https://isocpp.org/files/papers/P2809R3.html` / `http://wg21.link/P2809r3`):
  - §6 Language Wording: *“The controlling expression of a trivially empty iteration statement is the expression of a `while`, `do`, or `for` statement (or `true`, if the `for` statement has no expression). A trivial infinite loop is a trivially empty iteration statement for which the converted controlling expression is a constant expression, when interpreted as a constant-expression ([expr.const]), and evaluates to `true`.”*
  - §6: *“The statement of a trivial infinite loop is replaced with a call to the function `std::this_thread::yield` ([thread.thread.this]); it is implementation-defined whether this replacement occurs on freestanding implementations.”* Note: *“In a freestanding environment, concurrent forward progress is not guaranteed; such systems therefore require explicit cooperation. A call to yield can add implicit cooperation where none was otherwise intended.”*
  - §5 Rationale: the wording *“captures very narrowly a few forms”* and makes them equivalent to repeated `yield`; freestanding replacement is implementation-defined because it would add cooperation where none was intended.
  - §7 Effect table: `while(1);` / `for(;;);` → `while(1) yield()` under proposal; a loop with a *“meaningless statement in the body”* remains *undefined behavior* under proposed wording; a loop whose controlling expression *“isn't a constant expression which converts to true”* remains UB.

No performance numbers, scheduler benchmarks, or hardware inspection are claimed; this lab performs no C++ compilation, no binary execution, and no timing.

## Lab design

Pure **Python stdlib + shell**, no C++ compilers, no executed binaries, no scheduler benchmarks, no hardware inspection, no external packages, no network in evaluator. Every situation is a synthetic JSON record; the evaluator answers a *classification question* (“what does P2809R3 say about this syntactic/environment record?”), not “how does this run on hardware?”

### Fixtures (`fixtures/cases.json`)

12 synthetic loop records — each carries the facts the classifier must interpret:

| id | Tests |
|---|---|
| `while_true_semicolon_hosted` | `while(true);` — empty semicolon, const true, hosted → trivial, yield |
| `while_true_empty_braces_hosted` | `while(true){}` — empty braces, const true, hosted |
| `for_empty_implicit_true_hosted` | `for(;;){}` — implicit true, empty braces, hosted |
| `do_while_true_empty_braces_hosted` | `do{}while(true);` — do-while variant |
| `constexpr_true_hosted` | `constexpr bool go=true; while(go);` — constant-expression true via named constexpr |
| `while_true_string_literal_body` | `while(true){"x";}` — useless statement destroys trivially-empty |
| `while_non_const_condition_empty` | `while(!done);` — empty body but non-constant condition → not trivial |
| `runtime_infinite_not_trivial` | `while(true){external();}` — runtime endless, non-trivial body → not trivial |
| `qualifying_hosted_yield` | Qualifying hosted case — explicit hosted replacement |
| `qualifying_freestanding_impl_defined` | Same syntax under freestanding — implementation-defined |
| `while_constexpr_false_empty` | `while(false);` — empty but const false → not trivial |
| `while_true_continue_body` | `while(true)continue;` — `continue` is not trivially empty |

### Evaluator (`evaluator.py`)

`python3 evaluator.py` reads `fixtures/cases.json`, derives the seven separate output axes per case:

```
trivially_empty                      True | False
condition_is_constant_expression     True | False
condition_constant_value             True | False | None (null when not constant)
trivial_infinite_loop                True | False  (trivially_empty AND const-expr → true)
environment                          hosted | freestanding
yield_replacement_status             replaced_with_yield | implementation_defined | not_applicable
compiler_support_claim               {claim, is_normative=False, note}
```

No `cpp26_safe` / `portable` / `compliant` / `overall` field is emitted. Exit 0; writes `results.json` + `RESULTS.md`.

### Tests (`tests/test_cpp26_trivial_loop.py`)

Independent oracle — re-derives expected classifications from raw `body_is_trivially_empty` / `condition_*` / `environment` facts without calling the evaluator's decision helpers. Catches:

- treating a loop with a useless body statement as trivial
- treating `for(;;)` without honouring implicit `true`
- treating a non-constant empty-body loop as trivial
- treating a runtime-endless non-trivial loop as trivial
- conflating hosted `replaced_with_yield` with freestanding `implementation_defined`
- emitting an overall “C++26 safe / portable” verdict
- treating a compiler support claim as normative standard evidence

```
python3 -m unittest tests/test_cpp26_trivial_loop.py -v
```
